1. Arquitectura y Lenguaje del Sistema

El sistema está desarrollado bajo la plataforma ASP.NET Core 9.0 (Web App) utilizando el patrón arquitectónico MVC (Modelo-Vista-Controlador) combinado con el Patrón Repositorio tradicional sin EF Core, accediendo a una base de datos MySQL/MariaDB mediante ADO.NET clásico.

El Ecosistema Tecnológico

A diferencia de los proyectos que dependen de Entity Framework Core (un ORM automático), este desarrollo adopta la filosofía clásica de ADO.NET. Esto significa que escribimos comandos SQL crudos, abrimos conexiones de forma explícita y mapeamos los datos de los registros a clases utilizando lectores de datos.

ASP.NET Core 9.0 MVC

Separa la lógica de negocios (Modelo), la interfaz de usuario (Vista) y el enrutamiento/flujo de datos (Controlador).

ADO.NET Clásico

Utiliza bibliotecas nativas de MySQL para ejecutar consultas directas. Es veloz y permite un control completo del SQL.

Flujo de una Solicitud (Request Pipeline)

Cuando un usuario interactúa con la aplicación:

  1. El navegador hace una petición HTTP a una URL (ej. /Alumno/Index).
  2. El motor de enrutamiento analiza la URL y dirige la petición al Controlador correspondiente.
  3. El Controlador pide datos a través de una Interface de Repositorio.
  4. La implementación concreta del Repositorio se conecta a MySQL, ejecuta la consulta y devuelve los objetos Modelo.
  5. El Controlador inyecta estos modelos en la Vista Razor (.cshtml).
  6. La Vista se procesa en el servidor generando HTML dinámico que se envía de vuelta al navegador.

2. Modelos, Interfaces y Repositorios

El núcleo de datos está compuesto por las entidades de negocio (Modelos) y el contrato de acceso a datos (Interfaces) que desacopla la base de datos de la capa visual.

Los modelos representan las tablas de la BD en clases de C#. Cada propiedad mapea a una columna de la tabla.

Las interfaces definen el "contrato" de los métodos que los repositorios deben proveer. Esto permite cambiar el motor de base de datos sin afectar a los controladores.

No devuelve vistas HTML. En su lugar, devuelve datos en formato estructurado JSON para que sean renderizados en el cliente por Javascript.

// GET: api/alumnos
[HttpGet("api/alumnos")]
[Produces("application/json")]
public IActionResult ObtenerAlumnosApi([FromQuery] int pagina = 1, [FromQuery] string? q = null)
{
    try
    {
        if (!string.IsNullOrWhiteSpace(q))
        {
            var termino = q.Trim().ToLower();
            var resultados = _repoAlumno.ObtenerTodos()
                .Where(a => a.Nombre.ToLower().Contains(termino) || 
                            a.Apellido.ToLower().Contains(termino) || 
                            a.DNI.Contains(termino))
                .Take(10).ToList();
            return Ok(resultados); // Retorna HTTP 200 OK con el listado JSON
        }
        
        var lista = _repoAlumno.ObtenerPaginados(pagina, 10);
        return Ok(new { Resultados = lista, PaginaActual = pagina });
    }
    catch (Exception ex)
    {
        return BadRequest(new { Error = ex.Message }); // Retorna HTTP 400 Bad Request
    }
}

¿Qué es Vue.js y cómo funciona en este proyecto?

Vue.js es una librería de JavaScript para crear interfaces dinámicas. En la vista de alumnos no usamos compiladores; cargamos Vue directamente con una etiqueta script (CDN).

Los conceptos fundamentales para comprender el código son:

  • Montaje (mount('#app')): Vue toma el control de un div HTML con id="app" y hace que todo lo que esté dentro sea reactivo.
  • Reactividad (ref): Son variables especiales de JavaScript. Cuando cambias su valor (ej. miVariable.value = "hola"), Vue redibuja instantáneamente el HTML donde se use esa variable sin que recargues la página.
  • v-model: Enlace bidireccional. Si el usuario escribe en un campo de texto, la variable de JS cambia sola. Si la variable de JS cambia mediante código, el texto en pantalla se actualiza solo.
  • v-for: Bucle en HTML. Recorre un array de JS y clona la etiqueta HTML por cada elemento (ej. crear filas en una tabla).
  • v-if / v-else: Muestra u oculta bloques HTML según una condición.
  • @click: Ejecuta una función JS cuando el usuario hace clic en un elemento.

Ejemplo paso a paso del flujo de alumnos

<script>
    const { createApp, ref, onMounted } = Vue;

    createApp({
        setup() {
            // Variables reactivas
            const alumnos = ref([]);
            const cargando = ref(false);

            // Método asíncrono para cargar alumnos del servidor

        }

</script>

5. SQL, Conexión a BD y CRUD

Las clases de repositorio utilizan comandos ADO.NET para interactuar con la base de datos de manera directa y optimizada.

Cada consulta abre una conexión física a MySQL y la cierra inmediatamente al finalizar usando la directiva using de C#, que asegura la liberación de recursos.

public Alumno? ObtenerPorId(int id)
{
    Alumno? alumno = null;
    using (var connection = new MySqlConnection(connectionString))
    {
        var sql = "SELECT * FROM Alumnos WHERE AlumnoID = @id";
        using (var command = new MySqlCommand(sql, connection))
        {
            command.Parameters.AddWithValue("@id", id);
            connection.Open();
            using (var reader = command.ExecuteReader())
            {
                if (reader.Read())
                {
                    alumno = new Alumno {
                        AlumnoID = reader.GetInt32("AlumnoID"),
                        Nombre = reader.GetString("Nombre"),
                    };
                }
            }
        }
    }
    return alumno;
}

Lógica clásica para el comando Insertar (Alta) y Actualizar (Modificación) a la BD.

public int Alta(Alumno alumno)
{
    int idGenerado = 0;
    using (var connection = new MySqlConnection(connectionString))
    {
        var sql = @"
            INSERT INTO Alumnos (Nombre, Apellido, DNI, EscuelaID)
            VALUES (@Nombre, @Apellido, @DNI, @EscuelaID);
            SELECT LAST_INSERT_ID();";
            
        using (var command = new MySqlCommand(sql, connection))
        {
            command.Parameters.AddWithValue("@Nombre", alumno.Nombre);
            command.Parameters.AddWithValue("@Apellido", alumno.Apellido);
            command.Parameters.AddWithValue("@DNI", alumno.DNI);
            command.Parameters.AddWithValue("@EscuelaID", alumno.EscuelaID);
            
            connection.Open();
            idGenerado = Convert.ToInt32(command.ExecuteScalar());
        }
    }
    return idGenerado;
}

La paginación real evita traer miles de registros a la memoria del servidor. Se le indica a la base de datos que retorne solo una porción acotada usando LIMIT y OFFSET.

// OFFSET indica a partir de qué registro leer.
// LIMIT indica cuántos registros leer de allí en adelante.
public IEnumerable<Alumno> ObtenerPaginados(int pagina, int cantidad)
{
    int offset = (pagina - 1) * cantidad;
    var lista = new List<Alumno>();
    
    using (var connection = new MySqlConnection(connectionString))
    {
        var sql = @"
            SELECT a.*, e.Nombre AS NombreEscuela 
            FROM Alumnos a JOIN Escuelas e ON a.EscuelaID = e.EscuelaID
            ORDER BY a.Apellido, a.Nombre
            LIMIT @Offset, @Cantidad";
            
        using (var command = new MySqlCommand(sql, connection))
        {
            command.Parameters.AddWithValue("@Offset", offset);
            command.Parameters.AddWithValue("@Cantidad", cantidad);
            
            connection.Open();
            using (var reader = command.ExecuteReader())
            {
                while (reader.Read())
                {
                    // Mapeo manual a la lista
                }
            }
        }
    }
    return lista;
}

6. Seguridad y Login en el Sistema

La seguridad del sistema está implementada mediante autenticación por cookies en el lado del servidor y autorización basada en Roles (Administrador y Agente).

¿Cómo se autentica el usuario?

Cuando un usuario inicia sesión en la aplicación web, el proceso técnico es el siguiente:

  1. El usuario envía su email y contraseña en un formulario POST a /Auth/Login.
  2. El controlador busca al usuario por email y verifica si la contraseña es válida comparando su hash.
  3. Si las credenciales son válidas, se crea una identidad técnica (ClaimsIdentity) que almacena datos esenciales del usuario como su ID, Nombre completo, Rol y URL del Avatar.
  4. Esta identidad se firma y encripta en una Cookie de sesión (configurada en Program.cs).
  5. El navegador guarda la cookie y la envía automáticamente en cada petición posterior. El servidor valida esta cookie para saber si el usuario sigue logueado.
// Fragmento de inicio de sesión en AuthController.cs
var claimsPrincipal = _authService.CreateClaimsPrincipal(usuario);
await HttpContext.SignInAsync(CookieAuthenticationDefaults.AuthenticationScheme, claimsPrincipal);

¿Por qué no se guardan contraseñas en texto plano?

Guardar contraseñas tal cual las escribe el usuario es una vulnerabilidad crítica. En la base de datos se guarda un PasswordHash generado por la librería BCrypt.

Al registrarse o crear un usuario, encriptamos la contraseña:

// Guardar contraseña hasheada
model.PasswordHash = BCrypt.Net.BCrypt.HashPassword(password);

Al iniciar sesión, comparamos la contraseña escrita con la guardada. La función no desencripta el hash; realiza el cálculo matemático inverso para corroborar si coinciden:

// Verificar contraseña en AuthController.cs
bool contraseñaValida = BCrypt.Net.BCrypt.Verify(password, usuario.PasswordHash);

Políticas y Restricciones

El sistema cuenta con dos roles definidos: Administrador y Agente. Estos roles determinan a qué acciones tiene acceso el usuario logueado.

En los controladores se utiliza el atributo [Authorize]:

  • Acceso para cualquier usuario logueado: Decorar el controlador con [Authorize] a secas.
  • Acceso restringido a administradores: Decorar el método con [Authorize(Roles = "Administrador")]. Si un Agente intenta acceder, el servidor intercepta la petición y lo redirige a la página de Acceso Denegado (403).
// Ejemplo en AlumnoController.cs
[Authorize] // Todos los métodos requieren estar logueado
public class AlumnoController : Controller
{
    // ...
    
    [HttpPost]
    [Authorize(Roles = "Administrador")] // Solo administradores pueden eliminar
    public IActionResult DeleteConfirmed(int id)
    {
        _repoAlumno.Baja(id);
        return RedirectToAction("Index");
    }
}

7. JWT y APIs REST Securizadas

Las APIs REST son canales de comunicación que permiten a clientes externos (móviles, integraciones o frontends SPA) consumir e interactuar con el sistema sin intermediar páginas HTML completas. Para proteger este canal, el estándar moderno es JWT (JSON Web Token).

Estructura y Concepto de JSON Web Token

Un JWT es una cadena de texto codificada y firmada que viaja en la cabecera HTTP de cada petición. A diferencia de las cookies de sesión tradicionales, JWT no guarda estado en el servidor (Stateless). Toda la información del usuario viaja contenida dentro del propio token de manera segura.

Se divide en tres partes separadas por puntos (Header.Payload.Signature):

  • Header (Cabecera): Especifica el tipo de token (JWT) y el algoritmo de cifrado para firmarlo (ej: HMAC SHA256).
  • Payload (Carga Útil): Contiene la información o reclamos (Claims) del usuario: su ID, email, rol y la fecha de expiración del token. Esta sección se codifica en Base64 y es visible, por lo que nunca deben guardarse contraseñas o datos hiper-sensibles aquí.
  • Signature (Firma): Es el corazón de la seguridad. Se calcula tomando el Header y el Payload codificados y firmándolos con una Clave Secreta que solo conoce el servidor. Si alguien altera el payload en el camino para, por ejemplo, cambiarse el rol de "Agente" a "Administrador", la firma no coincidirá y el servidor rechazará la petición inmediatamente.

Flujo de Login y Uso del Token

Cuando un cliente externo quiere usar la API REST, sigue estos pasos:

  1. El cliente envía sus credenciales mediante un POST JSON a api/login.
  2. El servidor valida el email y la contraseña contra la base de datos MySQL (usando el hasheo de BCrypt).
  3. Si los datos son correctos, el servidor emite un JWT firmado que retorna en el cuerpo de la respuesta JSON.
  4. Para las siguientes peticiones a endpoints protegidos (como api/alumnos), el cliente debe adjuntar el token en la cabecera HTTP de autorización:
    Authorization: Bearer [TU_TOKEN_JWT]
  5. El middleware del servidor intercepta la petición, verifica matemáticamente que la firma del token sea válida usando su clave secreta y lee el rol y datos del usuario directamente de la cabecera sin conectarse a la BD en cada petición.

Configuración del Middleware en Program.cs

En el archivo de arranque de ASP.NET Core 9.0 indicamos cómo debe validar el servidor cada token que reciba en las cabeceras HTTP:

builder.Services.AddAuthentication(options => {
    options.DefaultScheme = CookieAuthenticationDefaults.AuthenticationScheme;
})
.AddCookie(...) // Para la app web tradicional
.AddJwtBearer(JwtBearerDefaults.AuthenticationScheme, options => {
    var jwtKey = builder.Configuration["Jwt:Key"];
    options.TokenValidationParameters = new TokenValidationParameters {
        ValidateIssuer = true,
        ValidateAudience = true,
        ValidateLifetime = true,
        ValidateIssuerSigningKey = true,
        ValidIssuer = builder.Configuration["Jwt:Issuer"],
        ValidAudience = builder.Configuration["Jwt:Audience"],
        IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(jwtKey))
    };
});

Emisión y Autorización Híbrida en Controladores

El ApiLoginController valida y emite el token firmado con la clave del servidor:

var key = Encoding.UTF8.GetBytes(_config["Jwt:Key"]);
var tokenDescriptor = new SecurityTokenDescriptor {
    Subject = new ClaimsIdentity(new[] {
        new Claim(ClaimTypes.NameIdentifier, usuario.UsuarioID.ToString()),
        new Claim(ClaimTypes.Email, usuario.Email),
        new Claim(ClaimTypes.Role, usuario.Rol)
    }),
    Expires = DateTime.UtcNow.AddHours(4),
    Issuer = _config["Jwt:Issuer"],
    Audience = _config["Jwt:Audience"],
    SigningCredentials = new SigningCredentials(new SymmetricSecurityKey(key), SecurityAlgorithms.HmacSha256Signature)
};
var token = new JwtSecurityTokenHandler().CreateToken(tokenDescriptor);
return Ok(new { Token = new JwtSecurityTokenHandler().WriteToken(token) });

En ApiAlumnosController, usamos una política de autenticación combinada (Cookies + JWT). Esto permite que el frontend dinámico en Vue.js acceda mediante la sesión de la cookie y, al mismo tiempo, los clientes externos de API lo hagan mediante el token JWT en el header:

[ApiController]
[Route("api/alumnos")]
// Acepta indistintamente autenticación basada en Cookie de MVC o Token JWT Bearer
[Authorize(AuthenticationSchemes = $"{CookieAuthenticationDefaults.AuthenticationScheme},{JwtBearerDefaults.AuthenticationScheme}")]
public class ApiAlumnosController : ControllerBase {
    // Endpoints API protegidos...
}

Conceptos clave para defender el tema frente a docentes

  • ¿Por qué no se usó Session/Cookies en la API REST? Las APIs REST son, por definición, sin estado (Stateless). Las cookies están acopladas al navegador y vulnerables a ataques de tipo CSRF. JWT es independiente del cliente (puede consumirlo un celular, un script de Python o un sistema externo).
  • ¿Cómo sabe el servidor que el usuario es válido sin conectarse a la base de datos? Porque el token contiene la firma criptográfica (Signature). Si el servidor puede verificar la firma usando la clave secreta guardada en su appsettings.json, tiene la garantía matemática de que el token fue generado por él mismo y no ha sido alterado. El servidor simplemente lee el rol "Administrador" del Payload (codificado) y le da acceso.
  • ¿Qué pasa si expira la sesión? El token tiene un claim exp (expiración). El middleware del servidor rechaza automáticamente cualquier petición que envíe un token cuya fecha actual supere a la de expiración, retornando un código HTTP 401 Unauthorized.
  • ¿Cómo conviven Cookies y JWT en este proyecto? Mediante la inyección de múltiples esquemas de autenticación en la configuración. Los controladores MVC convencionales redirigen al Login clásico (Cookie), mientras que el controlador de la API REST valida los headers de autorización mediante JWT Bearer y las llamadas AJAX mediante Cookie en forma simultánea gracias al parámetro AuthenticationSchemes.

¿Cómo se reciben y almacenan los archivos en el servidor?

Cuando un formulario HTML envía una imagen, el elemento <form> debe incluir obligatoriamente el atributo enctype="multipart/form-data". En C#, la propiedad IFormFile recibe el flujo binario (Stream) de la imagen subida.

  1. Verificación y creación del directorio: Con _webHostEnvironment.WebRootPath obtenemos la ruta física absoluta de la carpeta wwwroot del servidor y garantizamos su existencia física con Directory.CreateDirectory(...).
  2. Nombre único anti-colisión: Para evitar que dos usuarios sobreescriban archivos con el mismo nombre (ej: foto.jpg), generamos un identificador único global mediante Guid.NewGuid() concatenado con la extensión original del archivo.
  3. Escritura asíncrona en disco: Guardamos el archivo binario en disco usando FileStream y CopyToAsync.
  4. Persistencia de URL en BD: En la base de datos MySQL no se guarda la imagen completa (formato BLOB pesado); solo se almacena la ruta relativa web accesible (ej: /uploads/avatars/guid.png).
// Fragmento de subida de Avatar en UsuarioController.cs
if (usuario.AvatarFile != null && usuario.AvatarFile.Length > 0)
{
    string wwwRootPath = _webHostEnvironment.WebRootPath ?? "wwwroot";
    string uploadsFolder = Path.Combine(wwwRootPath, "uploads", "avatars");
    Directory.CreateDirectory(uploadsFolder); // Garantiza que la carpeta exista físicamente

    string fileName = Guid.NewGuid().ToString() + Path.GetExtension(usuario.AvatarFile.FileName);
    string path = Path.Combine(uploadsFolder, fileName);

    using (var fileStream = new FileStream(path, FileMode.Create))
    {
        await usuario.AvatarFile.CopyToAsync(fileStream);
    }
    usuario.AvatarURL = "/uploads/avatars/" + fileName; // Guardamos la ruta relativa web en MySQL
}

¿Por qué es necesario refrescar la Cookie de Sesión tras cambiar el avatar?

En ASP.NET Core, cuando el usuario inicia sesión se crea una Cookie cifrada que contiene sus reclamos o Claims (ID, Nombre, Rol y AvatarURL). El menú superior (_LoginPartial.cshtml) lee la foto de perfil directamente desde la Cookie cargada en memoria (User.FindFirst("AvatarURL")?.Value).

Si el usuario edita su perfil y sube una nueva foto, la base de datos MySQL se actualiza correctamente, pero la Cookie del navegador mantendría la URL de la foto antigua hasta que el usuario cierre y vuelva a iniciar sesión. Para solucionar esto de manera transparente y sin interrumpir la sesión, el controlador detecta si el perfil editado corresponde al usuario activo y regenera su Cookie en caliente:

// En UsuarioController.cs (Acción Edit POST) tras guardar cambios en MySQL:
var currentUserId = User.FindFirstValue(ClaimTypes.NameIdentifier);
if (!string.IsNullOrEmpty(currentUserId) && currentUserId == id.ToString())
{
    var usuarioActualizado = _repositorioUsuario.ObtenerPorId(id);
    if (usuarioActualizado != null)
    {
        // Re-generar la identidad con la nueva AvatarURL y refrescar la cookie de autenticación
        var claimsPrincipal = _authService.CreateClaimsPrincipal(usuarioActualizado);
        await HttpContext.SignInAsync(CookieAuthenticationDefaults.AuthenticationScheme, claimsPrincipal);
    }
}

Relación Uno a Muchos (1:N) de Fotos de Escuela y Borrado Físico

Cada Escuela puede poseer múltiples fotografías registradas en la tabla fotosescuela asociadas mediante la clave foránea EscuelaID.

  • Subida y vinculación en servidor: La acción AgregarFoto(FotoEscuela foto) en EscuelaController.cs procesa el archivo de tipo IFormFile, lo guarda en la carpeta wwwroot/uploads/escuelas/ e inserta el registro relacional en MySQL.
  • Borrado doble (Disco + BD): Al eliminar una foto (EliminarFoto), se realiza una limpieza en dos pasos: primero se elimina el archivo físico del disco rígido mediante System.IO.File.Delete(path) para evitar acumular archivos "fantasma" u huérfanos, y luego se elimina el registro en la base de datos.
// En EscuelaController.cs: Eliminación física en disco y lógica en BD
[HttpPost]
[Authorize(Roles = "Administrador, Agente")]
public IActionResult EliminarFoto(int id)
{
    var foto = _repoFoto.ObtenerPorId(id);
    if (foto == null) return NotFound();

    // 1. Eliminar archivo físico de la carpeta wwwroot
    string wwwRootPath = _webHostEnvironment.WebRootPath ?? "wwwroot";
    string path = Path.Combine(wwwRootPath, foto.FotoURL.TrimStart('/'));
    if (System.IO.File.Exists(path))
    {
        System.IO.File.Delete(path);
    }

    // 2. Eliminar registro relacional en la base de datos MySQL
    _repoFoto.Baja(id);
    return RedirectToAction(nameof(Details), new { id = foto.EscuelaID });
}

Conceptos clave para defender la carga de archivos frente a docentes

  • ¿Por qué no guardar la imagen completa como BLOB binario dentro de MySQL? Guardar archivos multimedia en campos BLOB o LONGBLOB de la base de datos aumenta drásticamente el tamaño del archivo .ibd/.sql, satura la memoria RAM del servidor MySQL en cada consulta SELECT, ralentiza las copias de seguridad y no permite que el servidor web responda con políticas de caché estándar del navegador. Guardar la ruta web relativa permite que ASP.NET Core sirva la imagen directamente desde el sistema de archivos a máxima velocidad.
  • ¿Por qué se utiliza Guid.NewGuid() para renombrar las imágenes al subirlas? Cumple tres funciones de seguridad e integridad:
    1. Evita sobreescritura: Impide que si dos usuarios suben un archivo llamado foto.jpg, uno pise la imagen del otro.
    2. Saneamiento de nombres: Elimina espacios, tildes, caracteres especiales o símbolos no válidos en URLs.
    3. Seguridad (Path Traversal): Previene ataques donde un usuario malintencionado intenta nombrar un archivo con rutas relativas como ../../config.json.
  • ¿Qué rol cumple el middleware app.UseStaticFiles() en Program.cs? Habilita a ASP.NET Core para atender y entregar archivos estáticos físicos ubicados dentro de la carpeta raíz web wwwroot (tales como imágenes PNG/JPG, hojas de estilo CSS y scripts JS). Sin esta directiva en Program.cs, cualquier intento de acceder a /uploads/avatars/... devolvería un código de error HTTP 404 Not Found.
  • ¿Cómo se evita que queden archivos basura al borrar registros en la base de datos? En el método EliminarFoto, antes de ejecutar la sentencia SQL DELETE con ADO.NET, se obtiene la ruta física en disco mediante Path.Combine(wwwRootPath, ...) y se invoca System.IO.File.Delete(path). De esta forma se garantiza que los archivos físicos eliminados se eliminen de wwwroot y no ocupen espacio inútilmente.
  • ¿Por qué el formulario HTML requiere enctype="multipart/form-data"? Por defecto, los formularios HTML envían datos de texto codificados como application/x-www-form-urlencoded. Al subir archivos binarios (imágenes), es obligatorio especificar multipart/form-data para que el navegador divida la petición HTTP en múltiples partes, enviando los campos de texto por un lado y los flujos de datos binarios por otro.

Preguntas clave de docentes sobre Vue.js + ASP.NET Core

  • ¿Por qué se usa Vue.js mediante CDN y no con Node.js / Webpack / Vite? Porque para proyectos que integran Razor Views en ASP.NET Core MVC, incluir Vue 3 vía CDN (https://unpkg.com/vue@@3/dist/vue.global.js) permite añadir reactividad inmediata en cliente sin necesidad de configurar compiladores complejos, pipelines de Node.js o mantener un servidor SPA independiente.
  • ¿Cómo se evita que el motor de Razor confunda los símbolos de Vue? Razor utiliza `@` para evaluar código C#. Para evitar que Razor intente compilar directivas de eventos de Vue como `@click` o `@submit`, se escribe un doble arroba @@click o @@submit.prevent en la vista Razor.
  • ¿Qué es la reactividad y por qué se usa ref()? En Vue 3 Composition API, ref() envuelve un valor primitivo u objeto en un Proxy reactivo. Cuando se cambia su propiedad .value en JS, Vue detecta el cambio automáticamente y actualiza la porción del DOM afectada en el HTML sin recargar la página.
  • ¿Cuál es la ventaja de conectar Vue a una Controller de API REST ([ApiController])? Garantiza la arquitectura desacoplada. La misma API (`/api/alumnos`) sirve tanto para la interfaz web interactiva con Vue.js como para futuros clientes (ej. una aplicación móvil Android o iOS) autenticados mediante tokens JWT.
